À quoi sert Git ?

Git est un système de gestion de versions distribué. Il enregistre l'évolution d'un projet, facilite le travail en équipe et permet de revenir à une version précédente.

Avant de commencer, vérifier l'installation et configurer son identité :

git --version
git config --global user.name "Prénom Nom"
git config --global user.email "adresse@example.com"

Le cycle de travail

Git distingue le répertoire de travail, la zone de préparation et le dépôt local. On choisit les modifications à enregistrer avant de créer un commit.

Modifier
Préparer
git add
Valider
git commit
Partager
git push

Créer ou récupérer

git init
git clone URL_DU_PROJET

init démarre un dépôt local. clone récupère un projet existant et son historique.

Contrôler ses changements

git status
git diff
git diff --staged

Ces commandes permettent de vérifier l'état du dépôt et le contenu exact des modifications.

Enregistrer

git add fichier.md
git commit -m "Ajoute la documentation"

Un commit doit représenter une modification cohérente et avoir un message explicite.

Consulter l'historique

git log --oneline --graph
git show

L'historique permet de comprendre l'origine d'une modification et de retrouver un commit.

Travailler avec les branches

Une branche isole une fonctionnalité ou une correction de la branche principale. Elle évite de mélanger plusieurs travaux en cours.

git switch -c nouvelle-fonctionnalite
git switch main
git merge nouvelle-fonctionnalite
git branch -d nouvelle-fonctionnalite

Résoudre un conflit

Lorsqu'une fusion entre en conflit, ouvrir les fichiers signalés, choisir le contenu final, puis valider la résolution :

git status
git add fichier-resolu.md
git commit

# Annuler une fusion encore en cours
git merge --abort

Collaborer avec un dépôt distant

Un dépôt distant permet de partager les commits avec les autres membres du projet. Le nom par défaut est généralement origin.

git remote -v
git fetch origin
git pull origin main
git push -u origin nouvelle-fonctionnalite

fetch télécharge les nouvelles références sans modifier les fichiers. pull récupère puis intègre les changements. push publie les commits locaux.

Conseil : vérifier git status avant un pull et éviter de forcer l'envoi sur une branche partagée.

Outils utiles

Mettre son travail de côté

git stash
git stash list
git stash pop

stash sauvegarde temporairement des modifications pour permettre un changement de branche.

Ignorer des fichiers

git rm --cached fichier.env
git check-ignore -v fichier.log

Le fichier .gitignore exclut les fichiers générés, locaux ou contenant des secrets.

Annuler proprement

git restore fichier.md
git revert IDENTIFIANT_DU_COMMIT

restore annule une modification locale. revert crée un nouveau commit d'annulation, adapté à un historique partagé.

Retrouver une ancienne position

git reflog

Le reflog aide à retrouver une branche ou un commit après un déplacement accidentel de HEAD.

Bonnes pratiques et résumé

  • Faire des commits petits et cohérents.
  • Vérifier git status et git diff avant chaque commit.
  • Ne jamais versionner de mot de passe, de clé privée ou de fichier .env.
  • Utiliser une branche dédiée pour chaque fonctionnalité ou correction.
  • Préférer git revert pour annuler un commit déjà partagé.
  • Utiliser git help commande pour consulter la documentation intégrée.
Attention : git reset --hard supprime les modifications concernées. Vérifier qu'aucun travail utile ne sera perdu avant de l'utiliser.
